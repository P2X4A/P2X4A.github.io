Eres analista de datos en el área de Recursos Humanos de una multinacional. Cada día llegan pedidos de listados: quién cobra comisión, quién tiene cierta letra en el nombre, quién entró en cierto mes. Este taller practica los filtros de `WHERE`, los comodines de `LIKE`, las funciones de texto y fecha, y el manejo de `NULL`.

**Cómo leerlo:** primero está el taller, con lo que se pide en cada ejercicio; después, la resolución paso a paso. Conviene intentar cada consulta antes de mirar la solución.

---

## 1. El esquema HR

El taller usa el esquema de ejemplo `HR` de Oracle (107 empleados, 27 departamentos, 19 cargos, 10 registros de historial, 23 ubicaciones, 25 países y 5 regiones). El usuario solo puede leerlo, así que todos los ejercicios son consultas `SELECT`. Las llaves se comprobaron en el diccionario de datos de la base.

| Tabla | Columnas | Llaves |
|---|---|---|
| `EMPLOYEES` | `employee_id`, `first_name`, `last_name`, `email`, `phone_number`, `hire_date`, `job_id`, `salary`, `commission_pct`, `manager_id`, `department_id` | PK employee_id. FK job_id, manager_id (a EMPLOYEES) y department_id |
| `DEPARTMENTS` | `department_id`, `department_name`, `manager_id`, `location_id` | PK department_id. FK manager_id y location_id |
| `JOBS` | `job_id`, `job_title`, `min_salary`, `max_salary` | PK job_id |
| `JOB_HISTORY` | `employee_id`, `start_date`, `end_date`, `job_id`, `department_id` | PK (employee_id, start_date). FK employee_id, job_id y department_id |
| `LOCATIONS` | `location_id`, `street_address`, `postal_code`, `city`, `state_province`, `country_id` | PK location_id. FK country_id |
| `COUNTRIES` | `country_id`, `country_name`, `region_id` | PK country_id. FK region_id |
| `REGIONS` | `region_id`, `region_name` | PK region_id |

- `EMPLOYEES` se une con `DEPARTMENTS` por `department_id` y con `JOBS` por `job_id`.
- `EMPLOYEES.manager_id` apunta a `EMPLOYEES.employee_id`: la tabla se relaciona consigo misma (jefe y subordinado).
- `DEPARTMENTS` llega a `LOCATIONS` por `location_id`, y `LOCATIONS` a `COUNTRIES` por `country_id`.
- `COUNTRIES` llega a `REGIONS` por `region_id`. `JOB_HISTORY` guarda los cargos anteriores de cada empleado.

### Reglas del taller

- Todas las tablas se escriben con el prefijo `hr.`, por ejemplo `hr.employees`.
- Los alias de tabla van sin `AS` (`hr.employees e`). El `AS` solo se usa en los alias de columna.
- El texto va entre comillas simples y distingue mayúsculas de minúsculas: `'Canada'` no es igual a `'canada'`.
- La concatenación es `||`. `FETCH FIRST n ROWS ONLY` limita las filas y va al final de la consulta.
- Las fechas se escriben con `DATE 'AAAA-MM-DD'` y se muestran con `TO_CHAR(fecha, 'DD/MM/YYYY')`.
- El esquema HR es de solo lectura: todos los ejercicios son consultas `SELECT`.
- Cada ejercicio indica cuántas filas y columnas debe devolver. Esas cifras salen de ejecutar la consulta en una base Oracle Database 19c con el esquema HR (107 empleados); con otra copia de HR los nombres, las fechas y algunas cifras pueden cambiar.

**Nivel:** Básico · **Tablas:** `employees`

**Debe devolver:** 3 filas y 2 columnas.

## 3. Resolución paso a paso

### Ejercicio 1 — Empleados con comisión

**Idea.** `NULL` significa «sin dato», no «cero». Por eso no se compara con `=` ni con `<>`: se pregunta con `IS NULL` o `IS NOT NULL`.

1. La comisión vive en la columna `commission_pct` de `hr.employees`; no hace falta ningún `JOIN`.
2. El filtro es `commission_pct IS NOT NULL`.
3. En el `SELECT` van solo las tres columnas pedidas.
4. `ORDER BY e.last_name, e.first_name` fija el orden: sin él, Oracle puede devolver las filas en cualquier orden.

```sql
SELECT e.first_name,
       e.last_name,
       e.commission_pct
FROM hr.employees e
WHERE e.commission_pct IS NOT NULL
ORDER BY e.last_name, e.first_name;
```

**Resultado en HR.** 35 filas y 3 columnas; se muestran las primeras 6 filas:

```text
FIRST_NAME  LAST_NAME  COMMISSION_PCT
----------  ---------  --------------
Ellen       Abel                  0.3
Sundar      Ande                  0.1
Amit        Banda                 0.1
Elizabeth   Bates                0.15
David       Bernstein            0.25
Harrison    Bloom                 0.2
```

**Ojo.** `commission_pct <> NULL` y `commission_pct != NULL` no dan error, pero devuelven cero filas: cualquier comparación con `NULL` no es verdadera.

### Ejercicio 2 — Salario dentro de un rango

**Idea.** `BETWEEN a AND b` es una forma corta de escribir `>= a AND <= b`.

1. Las dos condiciones salen de `hr.employees`: `department_id = 50` y `salary BETWEEN 2500 AND 3500`.
2. Se unen con `AND`, porque el empleado debe cumplir ambas.
3. `ORDER BY e.salary DESC, e.last_name` ordena del mayor al menor y, si empatan, por apellido.

```sql
SELECT e.first_name,
       e.last_name,
       e.salary
FROM hr.employees e
WHERE e.department_id = 50
  AND e.salary BETWEEN 2500 AND 3500
ORDER BY e.salary DESC, e.last_name;
```

**Resultado en HR.** 28 filas y 3 columnas; se muestran las primeras 6 filas:

```text
FIRST_NAME  LAST_NAME  SALARY
----------  ---------  ------
Trenna      Rajs         3500
Julia       Dellinger    3400
Laura       Bissot       3300
Jason       Mallin       3300
Samuel      McLeod       3200
Julia       Nayer        3200
```

**Ojo.** El valor menor va primero: `BETWEEN 3500 AND 2500` no da error, pero tampoco devuelve ninguna fila.

### Ejercicio 3 — Empieza por S y termina en n

**Idea.** En `LIKE`, el símbolo `%` reemplaza cualquier cantidad de caracteres (incluso ninguno) y `_` reemplaza exactamente uno.

1. Nombre que empieza por S: `first_name LIKE 'S%'`.
2. Apellido que termina en n: `last_name LIKE '%n'`.
3. Las dos condiciones se unen con `AND` y se ordena por `last_name`.

```sql
SELECT e.first_name,
       e.last_name
FROM hr.employees e
WHERE e.first_name LIKE 'S%'
  AND e.last_name LIKE '%n'
ORDER BY e.last_name;
```

**Resultado en HR.** 1 fila y 2 columnas:

```text
FIRST_NAME  LAST_NAME
----------  ---------
Shanta      Vollman
```

**Ojo.** En Oracle `LIKE` distingue mayúsculas de minúsculas: `'S%'` no encuentra «sandra». Si no sabes cómo está escrito el dato, compara contra `UPPER(first_name) LIKE 'S%'`.

### Ejercicio 4 — Apellidos de exactamente cinco letras

**Idea.** `LENGTH(texto)` cuenta los caracteres; compararlo con un número da el filtro.

1. La longitud se calcula con `LENGTH(e.last_name)`.
2. El filtro es `LENGTH(e.last_name) = 5`.
3. La longitud también se muestra como columna, con el alias `letras`.

```sql
SELECT e.last_name,
       LENGTH(e.last_name) AS letras
FROM hr.employees e
WHERE LENGTH(e.last_name) = 5
ORDER BY e.last_name;
```

**Resultado en HR.** 30 filas y 2 columnas; se muestran las primeras 6 filas:

```text
LAST_NAME  LETRAS
---------  ------
Baida           5
Banda           5
Bates           5
Bloom           5
Brown           5
Chung           5
```

**Ojo.** `LENGTH` cuenta espacios y guiones como caracteres: un apellido compuesto suma más de lo que parece.

**Variante.** El mismo filtro con comodines: `WHERE e.last_name LIKE '_____'` (cinco guiones bajos).

### Ejercicio 5 — Correo corporativo

**Idea.** `||` concatena texto en Oracle y `LOWER` pasa todo a minúsculas.

1. Los empleados salen de `hr.employees` filtrando `department_id = 90`.
2. En la tabla los correos están en mayúsculas (`SKING`), por eso el correo se arma con `LOWER(e.email) || '@empresa.com'`.
3. Se le pone el alias `correo_corporativo` y se ordena por apellido.

```sql
SELECT e.first_name,
       e.last_name,
       LOWER(e.email) || '@empresa.com' AS correo_corporativo
FROM hr.employees e
WHERE e.department_id = 90
ORDER BY e.last_name;
```

**Resultado en HR.** 3 filas y 3 columnas:

```text
FIRST_NAME  LAST_NAME  CORREO_CORPORATIVO
----------  ---------  -------------------
Lex         Garcia     lgarcia@empresa.com
Steven      King       sking@empresa.com
Neena       Yang       nyang@empresa.com
```

**Ojo.** `+` no concatena texto en Oracle: `e.email + '@empresa.com'` falla con `ORA-01722` (número no válido).

### Ejercicio 6 — Nombre en formato de lista

**Idea.** `UPPER` pasa todo a mayúsculas e `INITCAP` pone en mayúscula la primera letra de cada palabra.

1. Se filtra `department_id = 60`.
2. Se arma el texto con `UPPER(e.last_name) || ', ' || INITCAP(e.first_name)`.
3. `ORDER BY empleado` ordena por el alias: en `ORDER BY` sí se puede usar el alias de columna.

```sql
SELECT UPPER(e.last_name) || ', ' || INITCAP(e.first_name) AS empleado
FROM hr.employees e
WHERE e.department_id = 60
ORDER BY empleado;
```

**Resultado en HR.** 5 filas y 1 columna:

```text
EMPLEADO
----------------
JACKSON, Valli
JAMES, Alexander
MILLER, Bruce
NGUYEN, Diana
WILLIAMS, David
```

**Ojo.** El alias solo se puede usar en `ORDER BY`; en `WHERE` y `GROUP BY` hay que repetir la expresión.

### Ejercicio 7 — Teléfonos con guiones

**Idea.** `REPLACE(texto, buscar, reemplazo)` cambia todas las apariciones del texto buscado.

1. El filtro es `phone_number LIKE '1.515%'`: el texto fijo «1.515» seguido de cualquier cosa.
2. La transformación es `REPLACE(e.phone_number, '.', '-')`; en `REPLACE` el punto es un carácter normal, no un comodín.
3. Se le pone el alias `telefono` y se ordena por apellido y nombre.

```sql
SELECT e.first_name,
       e.last_name,
       REPLACE(e.phone_number, '.', '-') AS telefono
FROM hr.employees e
WHERE e.phone_number LIKE '1.515%'
ORDER BY e.last_name, e.first_name;
```

**Resultado en HR.** 21 filas y 3 columnas; se muestran las primeras 6 filas:

```text
FIRST_NAME  LAST_NAME   TELEFONO
----------  ----------  --------------
Shelli      Baida       1-515-555-0116
Hermann     Brown       1-515-555-0169
John        Chen        1-515-555-0110
Karen       Colmenares  1-515-555-0119
Daniel      Faviet      1-515-555-0109
Lex         Garcia      1-515-555-0102
```

**Ojo.** En `LIKE` el punto tampoco es comodín: los únicos comodines son `%` y `_`. El patrón `'1_515%'` devuelve las mismas filas, pero solo porque `_` acepta cualquier carácter, también un punto.

### Ejercicio 8 — Los cinco empleados más antiguos

**Idea.** Ordenar por fecha ascendente deja primero la más antigua, y `FETCH FIRST` corta el resultado.

1. Se ordena por la fecha real: `ORDER BY e.hire_date`, y el apellido desempata.
2. La fecha se formatea solo en el `SELECT`, con `TO_CHAR(e.hire_date, 'DD/MM/YYYY')`.
3. `FETCH FIRST 5 ROWS ONLY` va al final de la consulta.

```sql
SELECT e.first_name,
       e.last_name,
       TO_CHAR(e.hire_date, 'DD/MM/YYYY') AS fecha_contratacion
FROM hr.employees e
ORDER BY e.hire_date, e.last_name
FETCH FIRST 5 ROWS ONLY;
```

**Resultado en HR.** 5 filas y 3 columnas:

```text
FIRST_NAME  LAST_NAME  FECHA_CONTRATACION
----------  ---------  ------------------
Lex         Garcia     13/01/2011
Hermann     Brown      07/06/2012
William     Gietz      07/06/2012
Shelley     Higgins    07/06/2012
Susan       Jacobs     07/06/2012
```

**Ojo.** Si ordenaras por el alias `fecha_contratacion` (ya convertida a texto), el orden sería alfabético: «01/…» antes que «02/…» sin importar el año. Ordena siempre por la columna original.

**Variante.** `FETCH FIRST n ROWS WITH TIES` no corta los empates del último puesto. Aquí cuatro personas entraron el 07/06/2012, así que ordenando solo por `hire_date`, con `n` igual a 3 salen cinco filas. Si el `ORDER BY` incluye otra columna, como el apellido, ya no hay empate y salen tres.

```sql
SELECT e.first_name,
       e.last_name,
       TO_CHAR(e.hire_date, 'DD/MM/YYYY') AS fecha_contratacion
FROM hr.employees e
ORDER BY e.hire_date
FETCH FIRST 3 ROWS WITH TIES;
```

### Ejercicio 9 — Contratados en junio, julio o agosto

**Idea.** `EXTRACT(MONTH FROM fecha)` devuelve el número del mes, y `IN` compara contra una lista de valores.

1. El mes se extrae con `EXTRACT(MONTH FROM e.hire_date)`.
2. `IN (6, 7, 8)` equivale a tres comparaciones unidas por `OR`.
3. Se muestra la fecha formateada y se ordena por la fecha real y luego por apellido.

```sql
SELECT e.first_name,
       e.last_name,
       TO_CHAR(e.hire_date, 'DD/MM/YYYY') AS fecha_contratacion
FROM hr.employees e
WHERE EXTRACT(MONTH FROM e.hire_date) IN (6, 7, 8)
ORDER BY e.hire_date, e.last_name;
```

**Resultado en HR.** 27 filas y 3 columnas; se muestran las primeras 6 filas:

```text
FIRST_NAME  LAST_NAME  FECHA_CONTRATACION
----------  ---------  ------------------
Hermann     Brown      07/06/2012
William     Gietz      07/06/2012
Shelley     Higgins    07/06/2012
Susan       Jacobs     07/06/2012
Daniel      Faviet     16/08/2012
Nancy       Gruenberg  17/08/2012
```

**Ojo.** `EXTRACT(MONTH FROM ...)` devuelve un número (6), no el nombre del mes.

**Variante.** `TO_CHAR(e.hire_date, 'MM') IN ('06', '07', '08')` hace lo mismo comparando texto.

### Ejercicio 10 — Sin departamento o sin jefe

**Idea.** Dos condiciones con `IS NULL` unidas por `OR`: basta con que se cumpla una.

1. Sin departamento: `department_id IS NULL`.
2. Sin jefe: `manager_id IS NULL`.
3. Se unen con `OR`; con `AND` solo saldría quien carezca de las dos cosas a la vez.

```sql
SELECT e.first_name,
       e.last_name,
       e.department_id,
       e.manager_id
FROM hr.employees e
WHERE e.department_id IS NULL
   OR e.manager_id IS NULL
ORDER BY e.last_name;
```

**Resultado en HR.** 2 filas y 4 columnas:

```text
FIRST_NAME  LAST_NAME  DEPARTMENT_ID  MANAGER_ID
----------  ---------  -------------  ----------
Kimberely   Grant             (null)         149
Steven      King                  90      (null)
```

**Ojo.** `department_id = NULL` nunca es verdadero: para preguntar por un `NULL` siempre se usa `IS NULL`.

### Ejercicio 11 — Dos letras «a» en el nombre

**Idea.** No existe una función que cuente letras, pero se puede medir cuánto se acorta el texto al borrar la letra: largo original menos largo sin las «a».

1. `LOWER(e.first_name)` unifica mayúsculas y minúsculas.
2. `REPLACE(..., 'a', '')` borra todas las «a».
3. La diferencia de longitudes es la cantidad de «a» que había.
4. Esa cuenta se usa en el `SELECT`, en el `WHERE` (`>= 2`) y en el `ORDER BY`.

```sql
SELECT e.first_name,
       e.last_name,
       LENGTH(e.first_name)
         - LENGTH(REPLACE(LOWER(e.first_name), 'a', '')) AS cantidad_a
FROM hr.employees e
WHERE LENGTH(e.first_name)
        - LENGTH(REPLACE(LOWER(e.first_name), 'a', '')) >= 2
ORDER BY cantidad_a DESC, e.first_name, e.last_name;
```

**Resultado en HR.** 18 filas y 3 columnas; se muestran las primeras 6 filas:

```text
FIRST_NAME  LAST_NAME  CANTIDAD_A
----------  ---------  ----------
Alana       Walsh               3
Adam        Fripp               2
Alexander   James               2
Alexander   Khoo                2
Allan       McEwen              2
Alyssa      Hutton              2
```

**Ojo.** El alias `cantidad_a` no se puede usar en el `WHERE`: se repite la expresión o se envuelve la consulta en una vista en línea.

**Variante.** `REGEXP_COUNT(e.first_name, 'a', 1, 'i')` cuenta las coincidencias sin importar mayúsculas, y se usa igual: `WHERE REGEXP_COUNT(e.first_name, 'a', 1, 'i') >= 2`.

### Ejercicio 12 — Reino Unido y la tercera letra

**Idea.** El país no está en `employees`: hay que viajar por `employees`, `departments`, `locations` y `countries`. La tercera letra se saca con `SUBSTR(texto, posición, largo)`.

1. `hr.employees` guarda el departamento del empleado (`department_id`).
2. `hr.departments` guarda la ubicación del departamento (`location_id`).
3. `hr.locations` guarda el país de la ubicación (`country_id`).
4. `hr.countries` traduce el código al nombre. En esta base el Reino Unido figura como `United Kingdom of Great Britain and Northern Ireland`, así que el filtro es `country_name LIKE 'United Kingdom%'`.
5. `SUBSTR(e.first_name, 3, 1) = 'a'` toma 1 carácter a partir de la posición 3 y lo compara con «a».

```sql
SELECT e.first_name,
       e.last_name
FROM hr.employees   e
JOIN hr.departments d ON d.department_id = e.department_id
JOIN hr.locations   l ON l.location_id   = d.location_id
JOIN hr.countries   c ON c.country_id    = l.country_id
WHERE c.country_name LIKE 'United Kingdom%'
  AND SUBSTR(e.first_name, 3, 1) = 'a'
ORDER BY e.last_name;
```

**Resultado en HR.** 3 filas y 2 columnas:

```text
FIRST_NAME  LAST_NAME
----------  ---------
Charles     Johnson
Sean        Tucker
Clara       Vishney
```

**Ojo.** El nombre del país no es `United Kingdom` sino el largo: `c.country_name = 'United Kingdom'` devuelve cero filas, y su código es `GB`, no `UK`. Cuando un filtro por texto no trae nada, mira cómo está escrito el dato. Además, con `JOIN` interno quedan fuera los empleados sin departamento: no tienen ubicación, tampoco país.

**Variante.** `e.first_name LIKE '__a%'` (dos guiones bajos, la «a» y cualquier cosa después) hace lo mismo que `SUBSTR`. Y como `hr.locations` ya trae el código del país, también se puede filtrar con `l.country_id = 'GB'` y ahorrarse el `JOIN` a `hr.countries`.

```sql
SELECT e.first_name,
       e.last_name
FROM hr.employees   e
JOIN hr.departments d ON d.department_id = e.department_id
JOIN hr.locations   l ON l.location_id   = d.location_id
WHERE l.country_id = 'GB'
  AND e.first_name LIKE '__a%'
ORDER BY e.last_name;
```
