## Descripción

Esta guía reúne los ejercicios de álgebra relacional de **Bases de Datos 1**. El enunciado parte de un esquema comercial de cinco relaciones y pide once consultas que se resuelven con los operadores del álgebra relacional.

Cada consulta se resuelve aquí de dos formas: primero en **álgebra relacional extendida**, que es donde se ve la estructura de la operación, y después en **SQL**, que es donde se ve la misma estructura traducida. Ver las dos en paralelo deja claro qué constructor de SQL corresponde a cada operador.

## Los esquemas

| Relación | Atributos | Qué guarda |
| :-- | :-- | :-- |
| `CLIENTE` | Id_Cliente, Nombre, Dirección, Teléfono, IdLocalidad | Los clientes de la empresa, con su localidad |
| `PRODUCTO` | IdProducto, Descripción, Precio | El catálogo de productos |
| `FACTURA` | IdFactura, IdCliente, Fecha, Pagada | La facturación de la empresa |
| `DETALLE` | IdFactura, IdProducto, Cantidad, PrecioVta | Los productos vendidos en cada factura |
| `LOCALIDAD` | IdLocalidad, Nombre | Las localidades de la zona |

Dos detalles del esquema se notan antes de empezar: `CLIENTE` y `LOCALIDAD` tienen ambas un atributo `Nombre`, y `DETALLE` es la tabla puente entre `FACTURA` y `PRODUCTO`, con clave (IdFactura, IdProducto).

## La notación

| Operador | Significado |
| :-- | :-- |
| `σ` | Selección: filtra filas por una condición |
| `π` | Proyección: se queda con algunas columnas |
| `⋈` | Unión (join) de dos relaciones por una condición |
| `−` | Diferencia de conjuntos |
| `×` | Producto cartesiano |
| `ρ` | Renombrado de atributos o de la relación |
| `÷` | División: los valores que se combinan con todos los de otra relación |

## Los once ejercicios

### 1. Productos cuyo Id sea mayor a 100

**Álgebra relacional**

```text
π_{ IdProducto, Descripción } ( σ_{ IdProducto > 100 } ( PRODUCTO ) )
```

**SQL**

```sql
SELECT IdProducto, Descripcion
FROM PRODUCTO
WHERE IdProducto > 100;
```

El orden de los operadores no es un detalle: la selección va primero porque necesita `IdProducto`, y la proyección viene después precisamente para poder descartar esa columna.

### 2. Nombres de los clientes de Luján

**Álgebra relacional**

```text
π_{ C.Nombre } (
  σ_{ L.Nombre = 'Luján' } (
    ρ_{ C.Nombre → CNombre, L.Nombre → LNombre } (
      CLIENTE ⋈_{ CLIENTE.IdLocalidad = LOCALIDAD.IdLocalidad } LOCALIDAD
    )
  )
)
```

**SQL**

```sql
SELECT c.Nombre
FROM CLIENTE c
JOIN LOCALIDAD l ON c.IdLocalidad = l.IdLocalidad
WHERE l.Nombre = 'Luján';
```

El renombrado `ρ` es obligatorio en álgebra: las dos relaciones traen un atributo `Nombre` y, sin renombrarlos, la proyección no sabe a cuál se refiere. En SQL ese papel lo cumplen los alias `c` y `l`.

### 3. Cliente, factura, producto y cantidad, con más de 500 unidades

**Álgebra relacional**

```text
π_{ C.Nombre, IdFactura, IdProducto, Cantidad } (
  σ_{ Cantidad > 500 } (
    ρ_{ C.Nombre → CNombre } (
      CLIENTE ⋈_{ IdCliente } FACTURA ⋈_{ IdFactura } DETALLE
    )
  )
)
```

**SQL**

```sql
SELECT c.Nombre, f.IdFactura, d.IdProducto, d.Cantidad
FROM CLIENTE c
JOIN FACTURA f ON c.Id_Cliente = f.IdCliente
JOIN DETALLE d ON f.IdFactura  = d.IdFactura
WHERE d.Cantidad > 500;
```

La condición se aplica a `DETALLE` porque es la única relación que tiene `Cantidad`, y la proyección final conserva los cuatro atributos pedidos.

### 4. Clientes que no han comprado nada

**Álgebra relacional**

```text
π_{ Nombre } ( CLIENTE − π_{ IdCliente } ( FACTURA ) )
```

**SQL**

```sql
SELECT c.Nombre
FROM CLIENTE c
WHERE NOT EXISTS (
  SELECT 1 FROM FACTURA f WHERE f.IdCliente = c.Id_Cliente
);
```

En álgebra la diferencia de conjuntos ya resuelve el «no». En SQL hace falta el `NOT EXISTS`, y el `1` del `SELECT` es un placeholder: lo que importa es la condición de correlación.

### 5. Clientes que han comprado todos los productos de la empresa

**Álgebra relacional**

```text
D      ≡ π_{ IdCliente, IdProducto } ( FACTURA ⋈_{ IdFactura } DETALLE )
P      ≡ π_{ IdProducto } ( PRODUCTO )
Faltan ≡ π_{ IdCliente } ( ( π_{ IdCliente } (D) × P ) − D )

π_{ Nombre } ( CLIENTE )
  − π_{ Nombre } ( CLIENTE ⋈_{ CLIENTE.Id_Cliente = Faltan.IdCliente } Faltan )
```

**SQL**

```sql
SELECT c.Nombre
FROM CLIENTE c
WHERE NOT EXISTS (
  SELECT 1
  FROM PRODUCTO p
  WHERE NOT EXISTS (
    SELECT 1
    FROM FACTURA f
    JOIN DETALLE d ON f.IdFactura = d.IdFactura
    WHERE f.IdCliente = c.Id_Cliente
      AND d.IdProducto = p.IdProducto
  )
);
```

Este es el operador de división. La formulación con diferencia de conjuntos se lee así: se arma el producto cartesiano entre los clientes que compraron algo y todos los productos, se le quitan las combinaciones que sí ocurrieron, y los clientes que quedan con alguna combinación faltante son los que no compraron todo. Restarlos deja la respuesta.

El doble `NOT EXISTS` del SQL es exactamente lo mismo: no hay ningún producto del catálogo que este cliente no haya comprado.

### 6. IdFactura de las ventas cuya cantidad supera la cantidad vendida en la factura 18

**Álgebra relacional**

```text
π_{ D1.IdFactura } (
  σ_{ D2.IdFactura = 18 ∧ D1.Cantidad > D2.Cantidad } (
    ρ_{ D1 } ( DETALLE ) ⋈_{ D1.IdProducto = D2.IdProducto } ρ_{ D2 } ( DETALLE )
  )
)
```

**SQL**

```sql
SELECT DISTINCT d1.IdFactura
FROM DETALLE d1
JOIN DETALLE d2 ON d1.IdProducto = d2.IdProducto
WHERE d2.IdFactura = 18
  AND d1.Cantidad > d2.Cantidad;
```

La tabla se une consigo misma: una copia es la venta que se busca y la otra es la factura 18. La comparación es por producto, porque `DETALLE` tiene clave (IdFactura, IdProducto) y cada venta se mide contra la venta del mismo artículo en la factura 18.

### 7. Productos que no se han comprado en Luján

**Álgebra relacional**

```text
π_{ IdProducto } ( PRODUCTO )
  − π_{ IdProducto } (
      σ_{ L.Nombre = 'Luján' } (
        ρ_{ L.Nombre → LNombre } (
          PRODUCTO ⋈_{ IdProducto } DETALLE
                 ⋈_{ IdFactura } FACTURA
                 ⋈_{ IdCliente } CLIENTE
                 ⋈_{ IdLocalidad } LOCALIDAD
        )
      )
    )
```

**SQL**

```sql
SELECT p.IdProducto, p.Descripcion
FROM PRODUCTO p
WHERE NOT EXISTS (
  SELECT 1
  FROM DETALLE   d
  JOIN FACTURA   f ON d.IdFactura = f.IdFactura
  JOIN CLIENTE   c ON f.IdCliente = c.Id_Cliente
  JOIN LOCALIDAD l ON c.IdLocalidad = l.IdLocalidad
  WHERE d.IdProducto = p.IdProducto
    AND l.Nombre = 'Luján'
);
```

El camino de las uniones va desde el producto hasta la localidad: producto → detalle → factura → cliente → localidad. Es el precio de llegar a un atributo que está en el otro extremo del esquema.

### 8. Productos que se han vendido tanto en Luján como en Cortines

**Álgebra relacional**

```text
P_Luján ≡ π_{ IdProducto } (
  σ_{ L.Nombre = 'Luján' } (
    ρ_{ L.Nombre → LNombre } (
      PRODUCTO ⋈_{ IdProducto } DETALLE
             ⋈_{ IdFactura } FACTURA
             ⋈_{ IdCliente } CLIENTE
             ⋈_{ IdLocalidad } LOCALIDAD
    )
  )
)

P_Cortines ≡ π_{ IdProducto } (
  σ_{ L.Nombre = 'Cortines' } (
    ρ_{ L.Nombre → LNombre } (
      PRODUCTO ⋈_{ IdProducto } DETALLE
             ⋈_{ IdFactura } FACTURA
             ⋈_{ IdCliente } CLIENTE
             ⋈_{ IdLocalidad } LOCALIDAD
    )
  )
)

P_Luján ∩ P_Cortines
```

**SQL**

```sql
SELECT p.IdProducto, p.Descripcion
FROM PRODUCTO p
WHERE p.IdProducto IN (
  SELECT d.IdProducto
  FROM DETALLE   d
  JOIN FACTURA   f ON d.IdFactura = f.IdFactura
  JOIN CLIENTE   c ON f.IdCliente = c.Id_Cliente
  JOIN LOCALIDAD l ON c.IdLocalidad = l.IdLocalidad
  WHERE l.Nombre = 'Luján'
)
AND p.IdProducto IN (
  SELECT d.IdProducto
  FROM DETALLE   d
  JOIN FACTURA   f ON d.IdFactura = f.IdFactura
  JOIN CLIENTE   c ON f.IdCliente = c.Id_Cliente
  JOIN LOCALIDAD l ON c.IdLocalidad = l.IdLocalidad
  WHERE l.Nombre = 'Cortines'
);
```

Los dos `IN` son la intersección. Aquí sí, porque las dos referencias son conjuntos concretos y cerrados: Luján y Cortines.

### 9. Nombre de las localidades a las que se han vendido todos los productos

**Álgebra relacional**

```text
D      ≡ π_{ IdLocalidad, IdProducto } (
         ρ_{ L.Nombre → LNombre } (
           LOCALIDAD ⋈_{ IdLocalidad } CLIENTE
                     ⋈_{ IdCliente } FACTURA
                     ⋈_{ IdFactura } DETALLE
         ) )
P      ≡ π_{ IdProducto } ( PRODUCTO )
Faltan ≡ π_{ IdLocalidad } ( ( π_{ IdLocalidad } (D) × P ) − D )

π_{ L.Nombre } ( LOCALIDAD )
  − π_{ L.Nombre } (
      LOCALIDAD ⋈_{ LOCALIDAD.IdLocalidad = Faltan.IdLocalidad } Faltan
    )
```

**SQL**

```sql
SELECT l.Nombre
FROM LOCALIDAD l
WHERE NOT EXISTS (
  SELECT 1
  FROM PRODUCTO p
  WHERE NOT EXISTS (
    SELECT 1
    FROM DETALLE d
    JOIN FACTURA f ON d.IdFactura = f.IdFactura
    JOIN CLIENTE c ON f.IdCliente = c.Id_Cliente
    WHERE c.IdLocalidad = l.IdLocalidad
      AND d.IdProducto = p.IdProducto
  )
);
```

Es el mismo operador de división del ejercicio 5, con las localidades en lugar de los clientes. La estructura se repite porque el «todos» siempre se resuelve igual.

### 10. Clientes que tienen alguna factura sin pagar

**Álgebra relacional**

```text
π_{ C.Nombre } (
  ρ_{ C.Nombre → CNombre } (
    CLIENTE ⋈_{ IdCliente } σ_{ ¬Pagada } ( FACTURA )
  )
)
```

**SQL**

```sql
SELECT DISTINCT c.Nombre
FROM CLIENTE c
JOIN FACTURA f ON c.Id_Cliente = f.IdCliente
WHERE f.Pagada = FALSE;
```

El enunciado no declara el tipo de `Pagada`. Se asume booleano; si el atributo es texto, la condición pasa a ser `f.Pagada = 'No'`.

### 11. Clientes que han pagado todas sus facturas

**Álgebra relacional**

```text
π_{ C.Nombre } ( CLIENTE )
  − π_{ C.Nombre } (
      ρ_{ C.Nombre → CNombre } (
        CLIENTE ⋈_{ IdCliente } σ_{ ¬Pagada } ( FACTURA )
      )
    )
```

**SQL**

```sql
SELECT c.Nombre
FROM CLIENTE c
WHERE NOT EXISTS (
  SELECT 1
  FROM FACTURA f
  WHERE f.IdCliente = c.Id_Cliente
    AND f.Pagada = FALSE
);
```

Es el ejercicio 4 con una condición distinta: se resta el conjunto de clientes con alguna factura impaga al de todos los clientes. El resultado es el complemento del ejercicio 10.

## Tres trampas del enunciado

**El atributo `Nombre` está repetido.** Aparece en `CLIENTE` y en `LOCALIDAD`, y los ejercicios 2, 7, 8 y 9 unen las dos relaciones. En álgebra eso obliga a renombrar antes de proyectar; en SQL, a usar alias. Sin ese paso, la proyección devuelve dos columnas con el mismo nombre y la consulta deja de ser inequívoca.

**El ejercicio 6 no dice «del mismo producto».** La comparación tiene que hacerse por producto, y no por el total de la factura, porque la clave de `DETALLE` es (IdFactura, IdProducto): una factura puede tener varios productos y cada uno se compara con su homólogo de la factura 18.

**Dos ejercicios piden «todos» y no son intersecciones.** El 5 y el 9 son divisiones. La intersección solo sirve en el 8, donde las dos referencias son conjuntos cerrados y conocidos.

## Qué entrena esta guía

Pasar por el álgebra obliga a decidir qué operación corresponde a cada constructor de SQL: `IN` es una unión, `NOT EXISTS` es una diferencia de conjuntos, una subconsulta correlacionada es un renombrado con autoinforme, y el doble `NOT EXISTS` es una división.

La división aparece dos veces y es la parte que más cuesta: no tiene una forma canónica en SQL y su formulación en álgebra —producto cartesiano menos lo que sí ocurrió— es la que hace evidente por qué funciona.

Una advertencia sobre el alcance: las soluciones están bien en su forma, pero el resultado sobre datos reales depende de que `DETALLE` tenga la clave (IdFactura, IdProducto) y de que no queden facturas huérfanas. Si algún producto no aparece nunca en `DETALLE`, el ejercicio 5 devuelve la lista vacía, que es la respuesta correcta para una empresa con catálogo y ventas desalineados.
